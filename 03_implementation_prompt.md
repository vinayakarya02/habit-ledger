## 1. v1 build spec (executed)

This prompt was written by Claude in the session from my second prompt and then executed by Claude Code. It is kept as it was used. The v1 file layout (`app.js`, `styles.css`) has since been replaced.

> Build **Habit Ledger**, a click-through prototype for Nubra's PM intern take-home (Problem 03: Post-trade review). It turns a month of option-trading fills into the 2–3 repeated behaviours associated with excess losses. Each habit must be priced honestly, backed by evidence gates, and mapped to a guardrail, and next month's data must be checked for change.
>
> **Constraints**: Static site with no build step: `index.html`, `styles.css`, and ES modules `engine.js` (pure, no DOM), `data.js` (deterministic synthetic personas) and `app.js` (UI). The engine must be importable by Node (`node --test`), so the UI and the evals exercise identical code. No runtime LLM, no network calls, no credentials. Keep a persistent banner: "Simulated data · not connected to Nubra · not investment advice". Use only fixed thresholds. Never say "you would have made ₹X". Say "associated with ~₹X of excess losses".
>
> **Engine**: `parseCsv` → `buildPositions` (flat → flat; exclude open or flipped positions) → `buildUnits` (strategy legs grouped) → detectors H1–H5 (decision-time triggers, opportunity denominators) → baseline-excess cost `−(Σpnl − n·min(meanComparison,0))` with a thin-baseline fallback, and H3 as loss beyond the defined max loss → gates G1–G4, Strong/Moderate confidence, de-duplication by standalone cost, at most 3 confirmed habits → month comparison → `analyze(fills)`.
>
> **Synthetic data**: Aarav (H1, H2 planted; H4 below threshold), Meera (H3, H5), Kabir (disciplined, with near-miss traps). Seeded PRNG, explicit day specs, and a `manifest` of planted occurrences for independent ground-truth tests.
>
> **UI screens**: Start, Data check, Ledger (habit cards, evidence drawer, near misses, "What we checked"), Guardrail sheet, Next-month check-in, How it works. Also: upload error state, clean state, CSV template and sample downloads, mobile layout, light/dark themes, Indian ₹ formatting, and every number traceable.
>
> **Evals**: planted vs detected sets, cost arithmetic against an independent hand calculation, gates, de-duplication, Kabir's zero confirmed habits, malformed CSV, open-position exclusion, verdict logic, and copy that never claims causation.

## 2. v2 upgrade

### 2.1 My prompt (executed)

The full text is in `06_prompt_log.md`, entry 4 ("Mission: Transform Habit Ledger into a Standout Fintech Product"). It asked for:
- an audit of the existing app;
- modules A–I (overview, habit intelligence, trade explorer, evidence inspector, guardrail center, month-over-month tracking, data import, scenario lab, methodology);
- engineering requirements;
- a larger evaluation suite;
- a GitHub push;
- a deployment that keeps the same URL;
- updated documents.

### 2.2 Foundation, written directly by Claude Code (no sub-prompt)

These files were written directly, without delegating to sub-agents:
- `src/engine.js`:
  - parameterised detectors;
  - missing charges kept missing (never ₹0);
  - per-period analysis;
  - per-trade behaviour labels and defined trade statistics;
  - the sensitivity re-gate;
  - Fisher-exact and Wilson comparison;
  - guardrail templates and compliance.
- `src/import.js`: tolerant reader, header aliases, strict amount and timestamp parsing, row-level validation, duplicates.
- `src/lab.js`, `src/store.js` (reducer and selectors), `src/format.js`, `src/ui/*`, `src/views/shell.js` and `src/main.js`.
- The design system (`styles/tokens.css`, `base.css`, `components.css`).
- The render-matrix harness and the build script.

It also wrote **`src/views/CONTRACT.md`**, the specification every module agent built against.

### 2.3 Module build workflow (executed)

**Script:** [`prompts/module-build-workflow.js`](prompts/module-build-workflow.js) contains every prompt verbatim; only local paths are replaced with `<repo>`.

There were ten parallel pipelines:
- nine product modules;
- one test-suite author.

Each pipeline ran three stages:
1. **Build.** The agent owns exactly one view file and its stylesheet, or the new test files.
2. **Review.** An independent adversarial reviewer returns structured findings.
3. **Fix.** The original agent verifies each finding and fixes it within its own files. Anything needing a shared file goes back as a request.

That is 30 agents in total. Outcome:
- Every module reported 0 smoke problems.
- The tests author added 103 tests and found **6 real bugs**. They were recorded as `todo` tests instead of being patched behind the reviewers' backs.
- About 25 shared-file change requests came back.

### 2.4 Integration (Claude Code, direct)

The shared-file requests were applied directly:
- **The six bug fixes:**
  - decimal-comma amounts are rejected;
  - seconds ≥ 60 are rejected;
  - the import notice count is correct;
  - `initialState(null)` no longer crashes;
  - the p ≥ 0.5 sentence is grammatical;
  - a habit cut only by the 3-habit limit is no longer called an "overlap".
  
  Their `todo` markers were removed, so they are now hard tests.
- Plural-correct copy, and rank-aware wording for the next action.
- Round-half-away-from-zero for ₹ figures.
- Hash anchors on the Methodology page.
- Focus fallbacks and a live region.
- `aria-disabled` and select errors in shared components.
- Unified Nubra capability labels.
- New edge datasets in the render matrix: a limit cut and two real overlaps.
- A UI test file (`tests/ui.test.mjs`).

### 2.5 Integrated review workflow (executed)

**Script:** [`prompts/integrated-review-workflow.js`](prompts/integrated-review-workflow.js).

Five reviewers each took one lens:
- numbers and cross-module consistency;
- interaction and state;
- honesty and copy;
- accessibility and responsive design (in a real browser);
- the product as a whole.

Every finding was checked by **two independent skeptics** told to refute it. Only findings both skeptics confirmed were fixed. The results are in `05_evaluation.md` §4.

### 2.6 Fixes (Claude Code direct, plus the view-fix workflow, executed)

- **Engine, store, `main.js`, data and design-system findings** were fixed directly by Claude Code, each with a regression test (`tests/review-fixes.test.mjs`).
- **View findings** were fixed by [`prompts/view-fix-workflow.js`](prompts/view-fix-workflow.js). Nine agents (one per view file) applied their module's confirmed findings. An independent verifier per module then checked each item against rendered text, and a second fix pass ran where needed. 9/9 modules were verified as resolved.
